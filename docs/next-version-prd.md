# 下一版需求：问卷导入—关键词整理—审核填报

更新日期：2026-11-17。状态：待样表和业务规则验证的需求稿；新增功能均未实现。正式版本号与工期未定。

## 1. 目标与决策状态

目标用户是同学院少量辅导员。下一版让使用者在电脑程序内完成问卷读取、谈话关键词整理、草稿生成与修改、逐条审核和 SS 分批填报。

| 状态 | 内容 |
| --- | --- |
| 用户已明确 | 先给同学院几位辅导员试用；需要问卷导入、关键词转记录、审核与填报的具体方案 |
| 本文提出的首版范围 | 本地桌面工作流、`.xlsx` 文件、一个经样表确认的问卷模板、单条生成、逐条审核、继续使用本机浏览器填报 |
| 开发前需验证 | 实际样表、字段与身份来源、模型与设备、内容模板、数据使用条件；见第 9 节 |

## 2. 范围

### 2.1 必须交付

- 导入腾讯文档导出的问卷文件，保留原始问题、回答与源行定位。
- 从问卷生成学生近况摘要和谈话提纲；关联实际谈话关键词后生成谈话记录草稿。
- 输入真实谈话时间，编辑草稿，对照来源逐条审核。
- 本地保存素材、编辑结果和处理状态，关闭重开后继续办理。
- 仅将已审核的当前版本转换为现有填报引擎需要的数据，沿用保存确认和待核对机制。
- 保留旧标准谈话记录 Excel 的读取能力；桌面导入后同样经过审核。文件格式兼容，新增审核步骤是有意的行为变化。

### 2.2 后续再做

微信小程序、录音与转写、腾讯文档在线同步、多人共同后台、跨设备合并、跨辅导员去重、其他 SS 模块、模型训练/微调、多模型切换框架、批量 AI 生成、多个问卷的自动融合、自动心理诊断或风险定级。

首版不新增跨午夜谈话支持，时间采用同一自然日内的起止时间。原命令行旧流程保留累计 10 条试录限制，不新增读取新草稿库的入口；它不属于本版桌面审核工作流。

## 3. 操作流程与界面

1. **导入素材**：选择“问卷”或“旧标准记录”入口；问卷选择工作表，确认列对应关系，查看可导入行与问题行。
2. **整理记录**：选择某次问卷，新建该学生的整理项；问卷可先生成近况摘要与提纲。实际谈话后补充关键词和时间，生成或手工编写记录草稿。
3. **对照审核**：一侧显示原始问答、来源时间和谈话关键词，另一侧编辑最终记录；补齐待确认项，逐条确认审核。
4. **填报与续办**：筛选已审核记录，登录 SS，核对本批名单与数量，明确点击开始；查看已保存、失败或待核对结果。

具体布局可通过原型调整，保持同屏对照和明确状态。问卷读取、编辑和审核不依赖学校登录；开始填报必须登录就绪。无须新增应用账号或服务器。

## 4. 功能需求

### R01：问卷读取与字段对应

- 首版接收 `.xlsx`，支持用户选择工作表；表头行和实际列名按确认后的样表确定，不让模型猜测文件结构。
- 姓名和学号是身份必填项；学号沿用当前学校的 10 位数字规则，按文本读取。问卷提交时间可选，缺失时显示未提供。
- 使用者确认身份列、可选时间列和至少一列作为素材的问答列；不同题目的回答保持分列或分项呈现，不混成无法追溯的一段话。没有选择问答列时不能完成问卷导入。
- 映射到身份或时间的列不再作为问答重复读取；未知列由使用者决定是否纳入，不自动推断用途。
- 文件无法打开、未选工作表、缺少必填映射时，停止本次导入并明确错误。身份缺失、学号格式错误、选定时间无法解析等行级问题列出源行与原因；问题行不进入可生成、可提交队列，其他有效行可导入。
- 同一文件内容、工作表与源行的重复导入复用已有素材，不覆盖已有编辑。重新导出或内容变化形成新批次，不承诺自动识别为同一次提交。
- 同一学生多次回答保留为独立素材，人工选择本次使用的一份；不自动采用最新值或合并。同一学号姓名不一致时标出冲突，由使用者核对，不静默合并。
- 保留文件名、文件内容指纹、工作表、源行号、导入时间与问答快照；不改写源 Excel。后续源文件移动或修改不改变已有快照。

### R02：实际谈话素材与时间

- 每个整理项有独立记录标识，关联所选问卷。问卷素材本身不代表谈话已经发生。
- 更换关联问卷时仅允许选择当前学生的素材；身份纠错需同时确认源行归属，不能将另一学生的问卷附到当前记录。
- 关键词分别记录“学生在本次谈话中的表述”“辅导员已经做的工作”“双方后续约定”；没有提供的项目留空，不能补成已经发生的事实。
- 生成谈话记录草稿前，至少有一项实际谈话素材；只有问卷时仅提供摘要和提纲。最终审核还需由使用者确认实际谈话已经发生。
- 使用者填写谈话日期和起止时间，程序计算分钟数并派生时段。日期不晚于上海时区的当天，结束晚于开始，时长为正整数分钟。
- 问卷提交时间与谈话时间分开显示，不默认互相替代。素材发生变化后，已有草稿保留，但提示需要重新核对并撤销原审核状态。

### R03：摘要、提纲与草稿生成

- 首版确定一种模型接入方式与一版固定模板；单条显式触发，生成任务不冻结桌面界面。
- 所选问答全部为空时提示缺少近况素材，不能生成摘要或提纲；已有实际谈话关键词仍可用于整理本次记录。
- 摘要标明来自问卷自述；问卷与实际谈话不一致时分别呈现，不擅自判断哪一方正确，不把过去自述改成当前事实。
- 谈话草稿只整理已提供的信息，区分学生陈述、辅导员已做工作和后续约定。没有提供的情绪状态、效果、处置、承诺和诊断不得添加。
- 身份、日期、时段和时长由表格或使用者输入确定，模型不负责生成这些填报字段。
- 约 300 字是既有模板的参考长度，不能为凑字数虚构；最终内容非空且最多 1000 字，沿用当前字符计数口径。
- 来源和待确认项在草稿旁单独显示。首版用原始问答与关键词对照支持核对，不承诺逐句自动事实核验。
- 新生成结果先预览，由使用者选择采用；不直接覆盖已经手工修改的正文。采用结果后进入待审核状态。
- 模型不可用、超时或输出不符合约定时显示具体失败，保留输入及原草稿；不写入伪成功状态，不自动改用其他服务。人工编写和编辑是明确可选的工作方式。

### R04：编辑与审核

- 可编辑最终谈话内容、实际谈话素材和时间；身份纠错必须显式进行并保留导入快照，不能悄悄修改来源。
- 审核前检查身份、真实谈话确认、日期/时长、正文长度与尚未解决的待确认项。校验失败指出具体字段。
- 使用者逐条确认“内容及身份时间已核对，记录对应真实谈话”后，记录标为已审核；保存被审核版本与审核时间。
- 修改身份、关联问卷、关键词、时间或最终正文，或采用重新生成的正文，均撤销审核。仅保存编辑不等于审核完成；首版不提供一键审核整批。
- 已保存记录只读；如需更正，先在 SS 按学校流程处理，首版不提供自动更正或把修改稿当新记录重复新增的操作。
- 已提交但结果不确定的记录锁定内容，核对结果前不允许通过修改产生新指纹来再次提交。

### R05：本地续办

- 显式保存素材与编辑内容，并显示是否有未保存修改；切换记录或关闭时提示保存、放弃或取消。只有写盘成功才显示已保存编辑。
- 重新打开后恢复导入快照、关键词、正文、审核版本和处理状态；保存失败应报错，保留当前输入，不以默认空数据掩盖错误。
- 新数据放在现有系统应用数据目录。建议使用一个 SQLite 文件，利用标准库实现，不增加服务器或迁移框架；已有进度 JSONL 与待确认文件继续保留，不批量迁移或重写。
- 学校保存状态以既有确认进度和待确认标记为依据。程序在重开时对账；即使网页保存成功后、界面状态更新前退出，也不能漏认已有确认记录而再次提交。
- 首版按一位操作者的独立电脑或系统账号使用，不提供同一系统账号内的多人隔离、同步和并发编辑保证。

### R06：审核后填报

- 队列仅包含已审核、内容仍对应审核版本、尚未确认保存且没有待核对问题的记录。开始前再次按当前版本建立本批快照；运行中禁止编辑或重新生成该批记录。
- 保持默认每批新增 10 条及现有可选数量范围。问卷行数、草稿数和本批可新增条数分别统计。
- 复用 `import_records()`、`fill_and_save()` 的现有行为：登录准备、学生搜索姓名核对、实际填写核对、学校响应确认、停止边界和人工处理不确定结果。
- 明确拒绝保存时显示学校原因；网络或响应未确认时进入结果待核对并停止。没有人工核对前不自动重试保存。
- 有既有待确认标记时先处理它，再开始任何批次；确认已保存则记入确认进度，确认未保存才允许重新排队，不确定则继续阻止填报。
- 保持原精确指纹算法和历史跳过能力；不宣称可以识别不同电脑、不同辅导员或修改正文后的语义重复记录。
- 旧标准表格通过原读取规则导入为待审核记录，保留未来日期与异常学号处理、原文、历史进度合并和不改写源表的行为；原本已经确认保存的条目仍直接显示已保存。
- 仅登录测试模式始终禁用录入，包括全部记录已审核的情况。

### R07：数据与试点边界

- 学校密码只用于本次登录，保持成功或失败后清空；密码和浏览器会话不进入模型输入。
- 生成任务只读取当前学生所选素材与指定模板，不携带其他学生、全部问卷或个人进度。
- 实际数据是否可用于模型处理、运行位置、保管人、留存期限和退出试点后的处理方式，在开始真实数据试点前确定。
- 本机方案不默认外发素材。若采用校内或外部服务，实际发送内容和接收方必须明确，并满足学校允许的条件；不得默认作为训练数据使用。
- 新增日志不记录问答、关键词、草稿全文或凭据；提交进度沿用必要身份元数据并仅在本地保管。故障反馈使用虚构样本或经批准处理的材料。
- 通用安装包、Git 与测试夹具不包含真实学生资料、草稿库、会话或个人进度；不新增自动批量删除行为。

## 5. 最小数据约定与兼容点

下表描述需要保存的信息，不要求一行对应一张表。实现使用满足首版的最小结构。

| 信息 | 必要内容 | 约束 |
| --- | --- | --- |
| 问卷素材 | 独立标识、姓名/学号、原始问答、可选提交时间、文件指纹/工作表/源行、导入时间 | 快照不可被后续生成覆盖；同一学生可有多份 |
| 整理项 | 独立记录标识、所选素材、关键词、人工确认的谈话时间、摘要/提纲、最终正文、待确认项 | 首版每项关联一份问卷；旧记录可直接携带原有正文而不关联问卷 |
| 审核信息 | 当前修订号、已审核修订号、审核时间、真实谈话确认 | 影响审核的内容变化即撤销审核；无需保存完整历史版本树 |
| 填报关联 | 本次提交数据的精确指纹、提交结果及关联时间 | 本地记录标识与现有去重指纹分开；以确认进度/待确认标记对账 |

提交给原引擎的字段保持为 `id`、`name`、`date`、`slot`、`duration`、`content`、`key`。`date` 使用 `YYYY-MM-DD`，`duration` 为整数分钟；时段沿用开始时间的分界：`00:00 ≤ 开始时间 < 12:00` 为上午，`12:00 ≤ 开始时间 < 14:00` 为中午，`14:00 ≤ 开始时间 < 18:00` 为下午，`18:00 ≤ 开始时间 < 24:00` 为晚上。新记录标识、审核状态和素材字段不加入原指纹的计算，避免破坏历史识别。

旧表格工作表仍为“谈话记录”，列仍为“姓名、学号、谈话时间、谈话时长、谈话内容（约300字，可直接录入）”。原读取器在一次选中范围内拒绝重复学号，新问卷入口允许多次回答；两种规则应明确区分，不能把原规则直接套到问卷。

## 6. 状态与提交边界

| 显示状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| 待整理 | 已导入素材或新建整理项，正文未就绪 | 补充关键词/时间，生成或人工编辑 |
| 待审核 | 有正文但尚未审核，或审核后发生修改 | 保存、修改、逐项核对后审核 |
| 已审核待录入 | 当前版本审核有效且字段完整 | 加入批次；修改则回到待审核 |
| 录入中 | 本批快照正在处理 | 等待；可请求在当前保存核对后停止 |
| 已保存 | 学校明确成功，或人工核对确认已保存并记入进度 | 只读查看，排除出新增队列 |
| 保存失败 | 学校明确拒绝，本条未保存 | 查看原因；修改需重新审核，未修改可手动重试 |
| 结果待核对 | 保存是否成功尚不确定 | 锁定内容，人工核对；未确认前阻止任何新批次 |

素材导入失败、生成失败和本地写盘失败应显示在对应操作处，不冒充学校保存结果。重启时，已留有待确认标记的“录入中”转为结果待核对；已有确认指纹转为已保存；尚未触发保存且无待确认标记的未完成项仍可续办，不能一律当作已保存或直接重试未知提交。

## 7. 验收场景

以下均为未来实现的验收标准，不是本次文档整理的测试结果。确定性规则使用虚构数据自动验证；生成质量另用固定样本人工评估。

| 编号 | 场景与操作 | 必须得到的结果 | 验证方式 |
| --- | --- | --- | --- |
| AC01 | 导入确认模板，选工作表并完成字段对应 | 姓名/学号、各题回答与源行一致；原文件未改写 | 读取与界面测试 |
| AC02 | 缺必填映射或未选问答列；另有个别身份/时间异常行 | 映射错误阻止导入；问题行列明原因并阻止后续处理，有效行可导入 | 读取测试 |
| AC03 | 重复导入同一文件；再导入同学生另一份回答；尝试选择另一学生问卷 | 完全重复素材不新增、不覆盖编辑；另一份保留独立来源，由人选择；禁止跨学生错配 | 持久化与界面测试 |
| AC04 | 只有问卷，未提供实际谈话素材；另测问答全部为空 | 有回答时可生成摘要/提纲；不能生成已发生谈话的记录或通过最终审核；空回答提示缺少素材，不生成摘要 | 业务规则与人工评测 |
| AC05 | 提供真实关键词，包含未约定措施及问卷与谈话差异 | 只整理有依据的信息；缺失措施不补写，不擅自消除差异 | 固定样本人工评测 |
| AC06 | 修改手工正文后重新生成；模拟模型超时/不可用 | 新结果需显式采用；失败不覆盖输入/原正文、不自动换服务 | 模拟生成端与界面测试 |
| AC07 | 时间缺失/未来/逆序/跨午夜、时长非整分钟；正文空或超过 1000 字 | 对应字段阻止审核；修正后方可审核。12、14、18 点分界派生正确 | 业务规则测试 |
| AC08 | 审核后分别修改身份、问卷选择、关键词、时间和正文 | 原审核失效，不能进入本批；重新审核才恢复资格 | 审核规则与界面测试 |
| AC09 | 旧标准表导入，再登录或启用仅登录模式 | 旧格式仍可读；未审核不能开始，仅登录模式即使已审核也不能录入 | 原测试调整与回归 |
| AC10 | 混合已保存、未审核、已审核记录，设本批数量 2 | 只选前 2 条可新增的已审核记录，提交内容精确等于审核快照 | 队列与模拟站点测试 |
| AC11 | 学校返回成功，但列表数量刷新滞后 | 按保存响应与确认进度认定已保存，不因旧计数误报失败 | 既有浏览器测试回归 |
| AC12 | 学校明确拒绝保存 | 显示拒绝原因、不写确认进度；不自动重试，修改后需重新审核 | 模拟站点测试 |

## 8. 发布门槛与试点评估

### 8.1 必须通过的发布门槛

- 第 9 节标为阻塞真实试点或发布的事项已有结论并写回文档；所选问卷格式和模型接入方式可复现。
- AC01—AC18 均有对应结果记录；已有登录、停止、历史去重、学校拒绝和结果未确认等业务保障通过回归。因新增审核门槛而变化的旧界面断言同步更新。
- 建议准备至少 20 个固定文本样本，覆盖问卷、真实关键词、缺失信息、矛盾描述和长文本；开发调试与发布评估样本区分，记录模型/模板版本和运行设备。真实素材须先满足试点使用条件，否则使用虚构样本。
- 固定评测样本中，不得出现编造实际谈话、错误归属学生、虚构措施或承诺等关键事实错误；发现即修改方案并重评。通过样本不代表对所有未来输入保证无错误，人工审核始终保留。
- Windows 真机验收有实际记录；Mac 开发机和模拟站点通过不能替代它。真实 SS 新增记录只由辅导员使用获准的真实业务记录验证，开发测试不得自动提交虚构数据。

### 8.2 试点评估口径

先记录人工基线，再记录使用助手后的导入、整理/生成、修订审核和填报时间。区分实际操作时间与模型等待时间，采用难度和素材完整度相近的记录比较，避免只用生成耗时宣称收益。

建议以总耗时减少约 30% 为试点目标，样本量、基线和最终目标待确认。另记录关键事实纠错数、每条修订时间、明确失败/待核对次数和继续使用意愿；失败尝试和放弃的记录也计入，不挑选成功案例。
